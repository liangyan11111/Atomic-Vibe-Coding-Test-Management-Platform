### 2.3 【中等】InMemory Repository 数据污染风险

**问题位置**：`src/infrastructure/repositories/inmemory-testcase.repository.ts` 第 11 行

```typescript
export class InMemoryTestCaseRepository implements ITestCaseRepository {
  private data: TestCase[] = [...testCases];  // 初始化时复制一次
```

**问题分析**：
- 服务启动后，mock-data 的引用被复制到 `this.data`
- 后续的 `create`/`update`/`delete` 操作修改的是 `this.data`
- 但 Next.js 的热更新可能导致服务重启时状态重置

**更深层问题**：
- 作为 InMemory 实现，测试数据应该可以重置
- 但没有提供 `reset()` 方法
- 单元测试可能因数据状态残留而失败

**建议**：添加 reset() 方法
```typescript
reset() {
  this.data = [...testCases];
}
```

### 2.4 【中等】Vibe Chat API 错误处理不完整

**问题位置**：`src/app/api/vibe-chat/route.ts` 第 83-88 行

```typescript
} catch (error) {
  const errMsg = error instanceof Error ? error.message : 'Stream error';
  controller.enqueue(encoder.encode(`data: ${JSON.stringify({ error: errMsg })}\n\n`));
  controller.close();
}
```

**问题分析**：
- 流式响应中途出错时，可能已经发送了部分内容
- 直接 close() 可能导致前端收到不完整的响应
- 没有区分"可恢复错误"和"不可恢复错误"

**建议**：
```typescript
// 区分错误类型
if (error instanceof NetworkError) {
  // 网络错误 - 可以重试
  controller.enqueue(encoder.encode(`data: ${JSON.stringify({ error: '网络中断，是否重试？' })}\n\n`));
} else {
  // 不可恢复错误
  controller.enqueue(encoder.encode(`data: ${JSON.stringify({ error: '服务内部错误' })}\n\n`));
}
controller.close();
```

- **现状**：模型名称写死在代码中
- **期望**：可配置的 LLM 适配器
- **缺失**：多 Provider 支持、API Key 管理
